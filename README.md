# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose
## Быстрый запуск

```bash
docker compose up --build
```

После запуска сервис доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

## Swagger

Swagger UI:

```text
http://localhost:8080/swagger/
```

OpenAPI JSON:

```text
http://localhost:8080/swagger/openapi.json
```

## API

Базовый префикс: `/api/v1`

| Метод | Маршрут | Описание |
|---|---|---|
| `POST` | `/api/v1/tasks` | Создать задачу |
| `GET` | `/api/v1/tasks` | Список задач |
| `GET` | `/api/v1/tasks/{id}` | Получить задачу по ID |
| `PUT` | `/api/v1/tasks/{id}` | Обновить задачу |
| `DELETE` | `/api/v1/tasks/{id}` | Удалить задачу |
| `GET` | `/api/v1/tasks/occurrences` | Вхождения повторяющихся задач |

## Реализовано: повторяющиеся задачи

### Концепция

Каждая задача может иметь поле `recurrence` — правило повторения. Задача с правилом является шаблоном; конкретные даты выполнения (вхождения) вычисляются на лету, а не хранятся в базе. Это позволяет менять правило без каскадных изменений и не накапливать тысячи записей.

Правило хранится в колонке `recurrence JSONB` в таблице `tasks` (миграция `0002_add_recurrence.up.sql`).

### Типы повторений

**`daily`** — каждые N дней.

```json
{
  "type": "daily",
  "interval": 3,
  "start_date": "2026-05-01",
  "end_date": "2026-12-31"
}
```

`interval` по умолчанию равен `1` (каждый день). `end_date` опционален во всех типах.

**`monthly`** — в определённое число каждого месяца (от 1 до 31).

```json
{
  "type": "monthly",
  "day_of_month": 15,
  "start_date": "2026-05-01"
}
```

Месяцы, в которых указанного числа не существует (например, 30 февраля), пропускаются.

**`specific_dates`** — только в перечисленные даты.

```json
{
  "type": "specific_dates",
  "dates": ["2026-06-01", "2026-09-01", "2026-12-01"],
  "start_date": "2026-06-01"
}
```

**`even_odd`** — только по чётным или нечётным числам месяца.

```json
{
  "type": "even_odd",
  "parity": "even",
  "start_date": "2026-05-01"
}
```

### Получение вхождений

```
GET /api/v1/tasks/occurrences?from=2026-05-01&to=2026-05-07
```

Оба параметра обязательны, формат `YYYY-MM-DD`. Максимальный диапазон — 366 дней.

Ответ — список объектов с датой и задачей-шаблоном:

```json
[
  {
    "date": "2026-05-01",
    "task": { "id": 1, "title": "Ежедневный обзвон", "recurrence": { ... }, ... }
  },
  {
    "date": "2026-05-02",
    "task": { "id": 1, "title": "Ежедневный обзвон", "recurrence": { ... }, ... }
  }
]
```

Задачи без `recurrence` в ответ не включаются.

### Обратная совместимость

Все существующие эндпоинты работают без изменений. Поле `recurrence` в запросах на создание и обновление опционально — если не передать, задача остаётся обычной. Чтобы убрать правило у существующей задачи, нужно передать `"recurrence": null` в `PUT`.

### Допущения

- `end_date` не является обязательным. Задача без `end_date` повторяется бессрочно — диапазон ограничивается параметром `to` при запросе вхождений.
- Ограничение в 366 дней на диапазон запроса вхождений во избежание перегрузки.
- Изменение правила `recurrence` у существующей задачи немедленно меняет все будущие вхождения, так как они вычисляются, а не хранятся.
